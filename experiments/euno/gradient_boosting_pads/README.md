# PADS 단독 실험 — 실제 환자 데이터에서 Gradient Boosting (euno)

우리가 수집한 데이터를 **전혀 쓰지 않고**, 오픈소스 데이터셋 PADS만으로 학습·평가한
실험이다. 앞선 실험([`experiments/euno/gradient_boosting/`](../gradient_boosting/README.md),
이하 **저번 실험**)에서 전처리·모델·하이퍼파라미터를 그대로 두고 **데이터만
교체**했으므로, 두 결과의 차이는 데이터 차이로 해석할 수 있다.

## 요약

| | 저번 실험 (모사 떨림) | **이번 실험 (실제 환자)** |
| --- | ---: | ---: |
| balanced accuracy (recording) | 1.0000 | **0.7615** |
| balanced accuracy (참가자) | — | **0.8972** |
| AUROC (recording / 참가자) | 1.000 | 0.8496 / **0.9594** |
| fold 간 표준편차 | 0.0000 | 0.0371 |
| 주파수 feature 기여 | +0.8%p | **+5.3%p** |
| LightGBM − XGBoost | 0.0500 | **0.0005** |

세 줄 결론.

1. 실제 환자 떨림은 모사 떨림보다 **훨씬 어렵다.** 같은 모델이 0.24 떨어진다.
2. 저번 실험에서 포화 때문에 측정할 수 없었던 **주파수 feature의 기여가 처음으로
   명확하게 나왔다.**
3. 남은 병목은 모델이 아니라 **임계값 보정과 집계 방식**이다. 저번 실험에서 참가자
   한 명에게 발견한 문제가 160명 규모에서 재확인됐다.

> **읽기 전 주의.** 위 숫자를 성능 주장으로 인용하기 전에
> [4장](#4-이-분류기는-제대로-작동하는가)을 읽을 것. 하락폭 중 얼마가 "문제가
> 어려워서"이고 얼마가 "PADS 라벨이 부정확해서"인지 이 설계로는 분리할 수 없고,
> 원논문 벤치마크와 대조하지도 않았다.

> **참고: LightGBM은 실행마다 결과가 미세하게 달라진다.** 멀티스레드 히스토그램
> 계산이 bit 단위로 결정적이지 않기 때문이다. 반복 실행 시 balanced accuracy가
> 약 ±0.01 흔들린다(같은 조건에서 XGBoost는 완전히 동일하게 재현된다). **0.01
> 미만의 차이는 해석하지 말 것.**

탓으로 돌릴 수 있다.

## 1.3 바꾼 것 — 평가 절차

두 가지는 데이터 성격상 바꿀 수밖에 없었다.

**LOSO → 참가자 단위 층화 5-fold.** 참가자가 6명일 때는 LOSO가 6번이면 끝나지만
160명이면 모델당 160번 재학습이다. `StratifiedGroupKFold(n_splits=5)`로 묶으면
누수 방지 보장은 같으면서 비용이 현실적이다. fold당 테스트 참가자는 32명이다.

**참가자 단위 관점 추가.** 파킨슨 떨림은 흔히 한쪽 손에서만 나타나는데 PADS는
사람에게 라벨을 붙이고 recording은 손목별로 있다. 환자의 안 떠는 손이 그대로 오답
처리되므로, recording 단위와 별개로 참가자의 recording 중 **최대 확률**을 그 사람의
예측으로 보는 관점을 함께 기록했다. 저번 실험에는 없던 축이다.

**판정 임계값도 학습한다.** 저번 실험은 0.5 고정이었다. 이 데이터에서는 0.5가
구조적으로 잘못된 위치여서(3.4), 각 fold의 학습 부분을 다시 3-fold로 쪼갠
out-of-fold 확률에서 임계값을 고른다. test fold는 선택에 관여하지 않는다. 비교를
위해 0.5 고정 결과도 함께 보고한다.

**cross-dataset 평가는 하지 않았다.** 저번 실험은 dataset_a ↔ dataset_b 양방향을
봤지만, 이번은 단일 데이터셋이라 해당 축이 없다.

# 2. 데이터

PADS strict 코호트. 출처·라이선스·변환 방법은
[`data_sources/euno/pads/README.md`](../../../data_sources/euno/pads/README.md) 참고.

| 항목 | 값 |
| --- | --- |
| 참가자 | 160명 (tremor 81 / 건강 대조군 79) |
| recording | 1,569개 (tremor 796 / non_tremor 773) |
| 동작 과제 | Relaxed, RelaxedTask, StretchHold, LiftHold, HoldWeight |
| 센서 | 양 손목 Apple Watch, 가속도계 + 자이로스코프, 100 Hz |
| 길이 | 9.65 ~ 20.11초 |

tremor는 임상 소견에 떨림이 기록된 파킨슨병·본태성 떨림 환자, non_tremor는 건강
대조군이다.

계획한 1,600개 중 31개는 다운로드 실패로 빠졌다(2%). 특정 참가자나 라벨에 쏠리지
않았고 **참가자 160명은 모두 유지**됐다. 가장 많이 빠진 참가자도 recording 6개가
남았다.

# 3. 결과

## 3.1 성능이 크게 떨어졌다

| | 저번 실험 | **이번 실험** |
| --- | ---: | ---: |
| balanced accuracy | 1.0000 | **0.7615** |
| sensitivity | 1.000 | 0.716 |
| specificity | 1.000 | 0.807 |
| AUROC | 1.000 | 0.850 |
| 표준편차 | 0.0000 | 0.0371 |

**0.24 하락.** 저번 실험에서 모든 모델이 0.95를 넘었던 것은 모델이 좋아서가 아니라
문제가 쉬웠기 때문이라는 직접적인 증거다.

저번 실험의 tremor는 non_tremor보다 가속도 RMS가 17~24배 컸다. PADS 환자의 떨림은
그만큼 크지 않고, 대조군도 정지 상태가 아니라 과제를 수행 중이다.

**표준편차 변화가 그 못지않게 중요하다.** 저번 실험은 6개 fold가 모두 1.0000이라
모델 간 비교가 불가능했다. 이번에는 0.0371의 실제 변동이 있어 비교에 의미가 생긴다.

### fold별

| fold | 테스트 참가자 | BA | AUROC |
| ---: | ---: | ---: | ---: |
| 1 | 32 | 0.780 | 0.858 |
| 2 | 32 | 0.761 | 0.845 |
| 3 | 32 | 0.716 | 0.803 |
| 4 | 32 | 0.821 | 0.900 |
| 5 | 32 | 0.730 | 0.842 |

sensitivity가 specificity보다 일관되게 낮다. **저번 실험도 방향이 같았다** — 오분류
32건이 전부 떨림을 놓치는 false negative였다. 규모는 달라도 실패 방향은 동일하다.

## 3.2 주파수 feature의 기여가 처음으로 측정됐다

이 저장소의 핵심 연구 질문에 대한 답이며, **이번 실험의 가장 큰 기여**다.

| feature set | 저번 실험 | **이번 실험** |
| --- | ---: | ---: |
| B1 (시간 20개) | 0.9667 | 0.7083 |
| B2 (시간+주파수 52개) | 0.9750 | **0.7615** |
| **차이** | **+0.8%p** | **+5.3%p** |
| AUROC 차이 | 측정 불가 (양쪽 1.000) | **+8.2%p** (0.7676 → 0.8496) |

저번 실험까지 이 저장소는 네 번의 분석(로지스틱 회귀, 민감도 분석, 비선형 baseline,
gradient boosting)을 거쳤지만 주파수 효과가 +0.8%p에 그쳤고, 센서 조합과 window
길이를 바꾸면 **부호까지 뒤집혔다.** 포화 때문에 측정 해상도가 없었다.

참가자 160명에 난이도가 있는 데이터에서는 효과가 명확하다. 이 저장소가 처음으로
**"명시적 주파수 정보가 도움이 된다"**고 말할 수 있는 근거를 확보했다.

## 3.3 모델 간 차이가 사라졌다

| | 저번 실험 | **이번 실험** |
| --- | ---: | ---: |
| LightGBM B2 | 1.0000 | 0.7615 |
| XGBoost B2 | 0.9500 | 0.7610 |
| **차이** | **0.0500** | **0.0005** |

저번 실험의 0.05 차이는 알고리즘의 우열이 아니라 정규화 설정 하나의 효과였다.
XGBoost의 `min_child_weight=1.0`이 확신이 서면 분할을 막아버려 300개 트리 중
203개가 빈 껍데기가 됐던 현상이다(저번 실험 README 참고).

recording이 220개에서 1,569개로 늘자 그 차이가 사실상 소멸했다. **n이 작을 때의
모델 순위를 신뢰하면 안 된다**는 것을 같은 코드로 보여준 사례다.

## 3.4 임계값을 고르면 0.633 → 0.897

고정 임계값 0.5로 채점하면 참가자 단위 결과가 recording 단위보다 **나쁘다.**

| 관점 (임계값 0.5) | BA | sensitivity | specificity | **AUROC** |
| --- | ---: | ---: | ---: | ---: |
| recording 단위 | 0.7615 | 0.716 | 0.807 | 0.850 |
| 참가자 단위 (max) | **0.6331** | 0.990 | **0.276** | **0.959** |

그런데 **AUROC는 오히려 0.959로 더 높다.** 순위 정보는 더 좋은데 0.5에서 자르는
것이 틀렸다는 뜻이다. 확률 분포를 보면 양쪽 모두 0.5 위에 몰려 있다.

| | 25% | 중앙값 | 75% |
| --- | ---: | ---: | ---: |
| 건강 대조군 | 0.471 | 0.660 | 0.836 |
| 환자 | 0.986 | 0.998 | 0.999 |

### 임계값을 train fold에서만 고른다

`train_pads.py`는 이제 임계값도 학습한다. 각 outer fold의 **학습 부분만** 참가자
단위로 다시 3-fold로 쪼개 out-of-fold 확률을 만들고, 거기서 balanced accuracy를
최대화하는 값을 골라 test fold에 적용한다. test fold는 임계값 선택에 전혀
관여하지 않는다.

모델이 자기 학습 데이터에 대해 과도하게 확신하므로, 학습 예측에서 바로 임계값을
고르면 편향된다. 내부 분할이 그것을 막는다.

| 참가자 단위 (LightGBM B2) | BA | sensitivity | specificity | 임계값 |
| --- | ---: | ---: | ---: | ---: |
| 임계값 0.5 고정 | 0.6331 | 0.990 | 0.276 | 0.500 |
| **임계값 선택** | **0.8972** | 0.836 | 0.959 | 0.955 |

fold별로 고른 값이 0.910 / 0.963 / 0.968 / 0.966 / 0.966 으로 거의 일치한다.
우연히 맞은 것이 아니라 **0.5가 구조적으로 잘못된 위치**였다는 뜻이다.

**recording 단위에서는 효과가 없다** (0.7615 → 0.7637). 거기서는 0.5가 이미 거의
최적이다. 즉 고칠 대상은 모델이 아니라 **참가자 단위 판정 규칙 하나**다.

### 집계 방식보다 임계값이 중요하다

이전 판 문서는 "집계를 max에서 mean으로 바꾸면 0.627 → 0.844"라고 적었다. **그
권고는 철회한다.** 임계값 0.5라는 잘못된 조건에서 비교했기 때문에 나온 결론이었고,
임계값을 제대로 고르면 max가 mean보다 낫다. 편측성·간헐성을 고려하면 max가
임상적으로도 더 타당하다.

### uncertain 구간은 지금은 도움이 되지 않는다

로드맵은 `tremor` / `non_tremor` / `uncertain` 3상태를 요구한다. 확률이 애매한
구간을 판단 보류로 빼 보았다(구간도 train fold에서만 선택).

| 판정 비율 | 판정한 것의 BA |
| ---: | ---: |
| 100% | 0.923 |
| 92.5% | 0.919 |
| 83.8% | 0.930 |
| 75.0% | 0.917 |

**4분의 1을 보류해도 정확도가 그대로다.** 오류가 중간 확률 구간에 몰려 있지 않고
흩어져 있다는 뜻이다. 따라서 `uncertain`을 확률 밴드로 구현하면 안 되고, 로드맵이
원래 적어 둔 대로 **신호 품질 기준**(누락 sample, 심한 충격, 비정상 sampling)으로
만들어야 한다.

### 저번 실험과 같은 패턴이다

저번 실험에서 오분류 32건이 전부 참가자 `march` 한 명에게 몰렸는데, **march fold를
포함한 모든 fold의 AUROC가 1.000**이었다. 순위는 완벽한데 고정 임계값이 틀린 것이
원인이었다.

| | 저번 실험 (march) | **이번 실험 (참가자 단위)** |
| --- | --- | --- |
| 고정 0.5에서의 정확도 | 0.700 ~ 0.800 | 0.633 |
| AUROC | **1.000** | **0.959** |
| 원인 | 고정 0.5 임계값 | 고정 0.5 임계값 |
| 규모 | 참가자 1명 | **참가자 160명** |

**참가자 한 명에게서 본 현상이 160명 규모에서 재확인됐고, 이번에는 고쳐서 0.897까지
회복시켰다.** 남은 격차(AUROC 0.959 대 BA 0.897)는 개인별 기준선 보정이 다음
작업이라는 근거가 된다.

## 3.5 동작 과제별 — 저번 실험에 없던 축

저번 실험의 데이터는 동작 구분이 없어 이 분석이 불가능했다. LightGBM, 임계값 0.5.

| 과제 | 성격 | B1 | B2 | 개선 |
| --- | --- | ---: | ---: | ---: |
| LiftHold | 자세 유지 | 0.692 | 0.759 | +6.7%p |
| Relaxed | 안정 | 0.693 | 0.759 | +6.6%p |
| StretchHold | 팔 뻗기 | 0.680 | 0.745 | +6.5%p |
| RelaxedTask | 안정 + 인지 부하 | 0.711 | 0.762 | +5.1%p |
| HoldWeight | 부하 유지 | 0.728 | 0.744 | +1.6%p |

**읽을 수 있는 것은 하나뿐이다: 주파수 feature가 다섯 과제 모두에서 도움이 된다.**

**과제 사이의 순위는 해석하지 말 것.** B2 값이 0.744~0.762 범위에 몰려 있는데, 이는
요약에 적은 LightGBM의 실행 간 변동(약 ±0.01)과 같은 크기다. 실제로 이전 실행에서는
Relaxed가 최하위(0.743)였고 이번 실행에서는 HoldWeight가 최하위(0.744)다. 과제별
차이를 주장하려면 여러 seed로 반복하거나 XGBoost처럼 결정적으로 재현되는 모델로
확인해야 한다.

## 3.6 진단별 검출 — 저번 실험에 없던 축

LightGBM B2, 참가자 단위, 임계값 0.5, max 집계.

| 진단 | 인원 | 떨림으로 판정 | 비율 | 확률 중앙값 |
| --- | ---: | ---: | ---: | ---: |
| 본태성 떨림 | 21 | 21 | **1.000** | 0.999 |
| 파킨슨병 | 60 | 59 | 0.983 | 0.996 |
| 건강 대조군 | 79 | 58 | **0.734** | 0.660 |

이 표는 **임계값 0.5**에서의 결과이므로 3.4의 보정 문제가 그대로 드러난다. 환자는
거의 모두 잡지만 대조군의 73%가 오탐이다. 임계값을 선택하면 같은 모델에서 특이도가
0.959가 되므로 대조군 오탐은 약 4%로 떨어진다.

본태성 떨림이 파킨슨병보다 검출률이 높은 것은 본태성 떨림이 대체로 진폭이 크고
지속적이라는 임상 지식과 일치한다.

# 4. 이 분류기는 제대로 작동하는가

결과를 성능으로 인용하기 전에, 이 모델이 무엇을 할 수 있고 무엇을 못 하는지
분명히 해 둔다.

## 4.1 판별은 한다

| 지표 | 값 |
| --- | ---: |
| AUROC (recording 단위) | 0.850 |
| AUROC (참가자 단위) | **0.959** |
| fold 5개 balanced accuracy 범위 (recording) | 0.716 ~ 0.821 |

우연(0.5)보다 확실히 위이고 5개 fold가 모두 0.71 이상이다. 잡음이 아니라 실제
신호다. 환자와 건강 대조군을 **순서대로 줄 세우는 일은 잘한다.**

## 4.2 판정은 임계값을 고쳐야 쓸 만해진다

| 참가자 단위 | BA | sensitivity | specificity |
| --- | ---: | ---: | ---: |
| 임계값 0.5 고정 | 0.6331 | 0.990 | **0.276** |
| **임계값 선택 (3.4)** | **0.8972** | 0.836 | 0.959 |

0.5 고정에서는 건강한 사람의 72%를 떨림으로 잘못 판정해 **사용 불가능**했다.
임계값을 학습 fold에서만 고르도록 바꾸자 특이도가 0.276에서 0.959로 올라갔다.

남은 오류는 주로 놓치는 쪽이다(민감도 0.836). 환자 6명 중 1명을 놓친다.

## 4.3 원인은 모델이 아니라 결정 규칙이었다

AUROC 0.959와 balanced accuracy 0.633이 함께 나온다는 것은 순위는 맞는데 자르는
위치가 틀렸다는 뜻이고, 실제로 임계값만 바꿔 0.897까지 회복했다. 모델과 feature는
전혀 건드리지 않았다.

> **모델은 쓸 만한 정보를 뽑아내고 있었고, 그것을 결정으로 바꾸는 부분이 망가져
> 있었다.** 남은 격차(0.959 대 0.897)는 개인별 기준선 보정의 몫이다.

## 4.4 그래서 이 실험이 증명한 것과 증명하지 못한 것

**증명한 것**

1. 명시적 주파수 정보가 실제 환자 데이터에서 **측정 가능한 수준으로 기여한다**
   (+5.3%p, AUROC +8.2%p). 저장소의 핵심 연구 질문에 대한 첫 근거다.
2. 작은 데이터에서 매긴 **모델 순위는 신뢰할 수 없다** (0.0500 → 0.0005).
3. 고정 임계값의 실패는 **참가자 한 명의 특이사례가 아니라 구조적 문제**이며
   (march 1명 → 160명에서 재현), **학습 fold에서 임계값을 고르는 것만으로
   0.633 → 0.897까지 회복된다.**
4. `uncertain`을 확률 밴드로 만드는 방식은 **이 데이터에서 효과가 없다.**

**증명하지 못한 것**

1. **성능 숫자 자체는 주장으로 쓸 수 없다.** 저번 실험 대비 하락 중 얼마가 "문제가
   어려워서"이고 얼마가 "라벨이 부정확해서"인지 현재 설계로 분리 불가능하다.
2. **"모사 떨림이 실제 떨림의 대리물인가"에는 답하지 않았다.** 그 질문은 우리
   데이터로 *학습*하고 PADS로 *평가*해야 답이 나온다. 이번은 PADS로 학습하고
   PADS로 평가했으므로 다른 질문이다.
3. **원논문 벤치마크와 대조하지 않았다.** PADS 원논문(Varghese et al., 2024)이
   같은 데이터로 ML 결과를 보고했는데 이 실험은 그 수치와 비교하지 않았다. 따라서
   현재 수치가 이 데이터에서 타당한 수준인지 **판단할 기준이 없다.** 가장 먼저
   해소해야 할 공백이다.

## 4.5 한 줄 판정

> **연구 베이스라인으로는 쓸 만해졌다**(참가자 단위 0.897, 특이도 0.959).
> **제품으로는 아직 아니다.** 학습 데이터의 non-tremor가 거의 전부 안정·자세 유지
> 상태여서, 걷기나 양치질 같은 일상 동작에서 어떻게 반응할지에 대한 근거가 전혀
> 없다. 그것은 모델이 아니라 데이터 수집(로드맵 3단계)의 문제다.

# 5. 한계

1. **라벨이 약하다.** 참가자 단위 진단에서 도출했다. 환자가 해당 20초 동안 실제로
   떨고 있었는지는 보장되지 않는다. 성능 하락의 일부는 모델이 아니라 라벨 잡음일 수
   있고, 현재 설계로는 둘을 분리할 수 없다(4.4 참고). **저번 실험은 수집 시 지시로 라벨이
   확실했으므로, 이 항목은 두 실험을 직접 비교할 때 가장 큰 교란 요인이다.**
2. **편측성 떨림을 다루지 못했다.** 양 손목에 같은 라벨을 붙였다. 임상 소견의 좌/우
   표현을 파싱하면 개선 여지가 있다.
3. **약물 상태를 통제하지 않았다.** PADS는 복약 상태를 recording 단위로 제공하지
   않는다.
4. **임계값 선택은 적용했지만 개인화는 아직이다.** 3.4로 0.633 → 0.897까지
   왔으나, 전원에게 같은 임계값(약 0.955)을 쓴다. 사람마다 떨림 강도가 다르므로
   개인별 기준선 보정이 남은 개선 여지다.
5. **PADS만의 결과다.** 우리 데이터로 학습해 PADS로 평가하는 **전이 실험은 하지
   않았다.** 그것이 "모사 떨림이 실제 떨림의 대리물인가"에 대한 직접적인 답이 되며,
   다음 단계로 남는다.
6. 31개 recording이 다운로드 실패로 빠졌다(2%).

# 6. 다음 작업 제안

3.4의 임계값 선택은 **이미 적용했다.** 아래는 그다음 순서다.

1. **원논문 벤치마크와 대조한다.** 4.4에서 지적한 대로, 이 대조 없이는 현재 수치가
   타당한 수준인지 판단할 수 없다. 다른 모든 해석의 전제가 된다.
2. **개인별 기준선 보정.** 저번 실험의 `march`와 PADS 환자 모두 실패 원인이 "학습
   분포보다 약한 떨림"이었다. 진폭 feature를 그 사람 자신의 하위 분위수로 정규화하면
   절대 진폭 의존을 줄일 수 있다. 웨어러블에서는 착용 초기에 개인 기준선을 수집하면
   된다. AUROC 0.959와 BA 0.897 사이의 격차가 여기서 줄어들 여지다.
3. **우리 데이터 → PADS 전이 실험.** 저장소의 외적 타당도에 직접 답한다.
4. **recording 집계를 median에서 바꾼다.** 떨림은 간헐적인데 median은 20초 중 3초만
   떨린 경우를 지운다. window 단위 max 또는 attention pooling이 맞고, 저장소
   프로토콜에 이미 gated-attention MIL이 적혀 있다.
5. 임상 소견에서 편측성을 파싱해 손목별 라벨을 정교화한다. 4.4의 "증명하지 못한
   것" 1번(라벨 잡음과 난이도의 분리)에도 부분적으로 기여한다.
6. Relaxed 과제가 가장 낮은 원인을 확인한다.

# 7. 실행 방법

macOS에서 LightGBM과 XGBoost는 OpenMP 런타임이 필요하다.

```bash
brew install libomp
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip install lightgbm==4.7.0 xgboost==3.4.1
```

PADS 데이터를 먼저 준비한다. 전체 코호트는 파일이 1,600개라 시간이 걸린다.

```bash
.venv/bin/python data_sources/euno/pads/download_or_prepare.py --dry-run
.venv/bin/python data_sources/euno/pads/download_or_prepare.py
```

그다음 평가를 실행한다.

```bash
MPLCONFIGDIR=/tmp/ada_iot_mpl .venv/bin/python experiments/euno/gradient_boosting_pads/train_pads.py
```

recording feature는 `results/pads_recording_features_3s.csv`에 캐시된다. 다시
계산하려면 `--rebuild-features`를 붙인다.

검증 환경: Python 3.12.14, numpy 2.3.2, pandas 2.3.1, scipy 1.16.1,
scikit-learn 1.7.1, lightgbm 4.7.0, xgboost 3.4.1.
