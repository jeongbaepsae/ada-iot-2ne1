# PADS 단독 실험 — 실제 환자 데이터에서 Gradient Boosting (euno)

우리가 수집한 데이터를 **전혀 쓰지 않고**, 오픈소스 데이터셋 PADS만으로 학습·평가한
실험이다. 앞선 실험([`experiments/euno/gradient_boosting/`](../gradient_boosting/README.md),
이하 **저번 실험**)에서 전처리·모델·하이퍼파라미터를 그대로 두고 **데이터만
교체**했으므로, 두 결과의 차이는 데이터 차이로 해석할 수 있다.

## 요약

| | 저번 실험 (모사 떨림) | **이번 실험 (실제 환자)** |
| --- | ---: | ---: |
| balanced accuracy | 1.0000 | **0.7626** |
| AUROC | 1.000 | 0.8513 |
| fold 간 표준편차 | 0.0000 | 0.0412 |
| 주파수 feature 기여 | +0.8%p | **+6.2%p** |
| LightGBM − XGBoost | 0.0500 | **0.0016** |

세 줄 결론.

1. 실제 환자 떨림은 모사 떨림보다 **훨씬 어렵다.** 같은 모델이 0.24 떨어진다.
2. 저번 실험에서 포화 때문에 측정할 수 없었던 **주파수 feature의 기여가 처음으로
   명확하게 나왔다.**
3. 남은 병목은 모델이 아니라 **임계값 보정과 집계 방식**이다. 저번 실험에서 참가자
   한 명에게 발견한 문제가 160명 규모에서 재확인됐다.

# 1. 저번 실험과 무엇이 달라졌나

## 1.1 고정한 것 — 비교 가능성의 근거

아래는 **의도적으로 건드리지 않았다.** 이것들이 같기 때문에 결과 차이를 데이터
탓으로 돌릴 수 있다.

| 항목 | 값 |
| --- | --- |
| 전처리 코드 | `scripts/run_baseline_analysis.py`를 그대로 import |
| 리샘플링 | 50 Hz 선형 보간 |
| window | 3초, 50% overlap, gap 100 ms 초과 시 제외 |
| feature | B1 시간 20개 / B2 시간+주파수 52개 |
| 모델 | LightGBM (주) + XGBoost (대조) |
| 하이퍼파라미터 | 저번 실험 `train.py`에서 import (사전 고정, 튜닝 없음) |
| 예측 단위 | recording |
| 판정 임계값 | 0.5 |
| 누수 방지 | 같은 사람이 train과 test에 동시에 들어가지 않음 |

## 1.2 바꾼 것 — 데이터

| 항목 | 저번 실험 | **이번 실험** |
| --- | --- | --- |
| 데이터 출처 | 팀이 직접 수집 (dataset_a + b) | **PADS (PhysioNet 공개)** |
| 떨림 종류 | 건강한 사람의 **모사 떨림** | **실제 환자의 병적 떨림** |
| 참가자 | 6명 | **160명** |
| recording | 220개 | **1,569개** |
| 유효 window | 2,614개 (26개 제외) | **12,225개 (2개 제외)** |
| 라벨 근거 | 수집 시 지시 — **강한 라벨** | 참가자 단위 임상 진단에서 도출 — **약한 라벨** |
| non-tremor의 의미 | 가만히 정지 | **건강한 사람이 과제 수행 중** |
| 센서 위치 | 손목 1개 | **양 손목** |
| 원 sampling | 100 Hz / 50 Hz (혼재) | 100 Hz (균일) |
| timestamp 품질 | dataset_b에 gap 19건 | gap 1건 |

## 1.3 바꾼 것 — 평가 절차

두 가지는 데이터 성격상 바꿀 수밖에 없었다.

**LOSO → 참가자 단위 층화 5-fold.** 참가자가 6명일 때는 LOSO가 6번이면 끝나지만
160명이면 모델당 160번 재학습이다. `StratifiedGroupKFold(n_splits=5)`로 묶으면
누수 방지 보장은 같으면서 비용이 현실적이다. fold당 테스트 참가자는 32명이다.

**참가자 단위 관점 추가.** 파킨슨 떨림은 흔히 한쪽 손에서만 나타나는데 PADS는
사람에게 라벨을 붙이고 recording은 손목별로 있다. 환자의 안 떠는 손이 그대로 오답
처리되므로, recording 단위와 별개로 참가자의 recording 중 **최대 확률**을 그 사람의
예측으로 보는 관점을 함께 기록했다. 저번 실험에는 없던 축이다.

**cross-dataset 평가는 하지 않았다.** 저번 실험은 dataset_a ↔ dataset_b 양방향을
봤지만, 이번은 단일 데이터셋이라 해당 축이 없다.

# 2. 데이터

PADS strict 코호트. 출처·라이선스·변환 방법은
[`data_sources/euno/pads/README.md`](../../../data_sources/euno/pads/README.md) 참고.

| 항목 | 값 |
| --- | --- |
| 참가자 | 160명 (tremor 81 / 건강 대조군 79) |
| recording | 1,569개 (tremor 796 / non_tremor 773) |
| 동작 과제 | Relaxed, RelaxedTask, StretchHold, LiftHold, HoldWeight |
| 센서 | 양 손목 Apple Watch, 가속도계 + 자이로스코프, 100 Hz |
| 길이 | 9.65 ~ 20.11초 |

tremor는 임상 소견에 떨림이 기록된 파킨슨병·본태성 떨림 환자, non_tremor는 건강
대조군이다.

계획한 1,600개 중 31개는 다운로드 실패로 빠졌다(2%). 특정 참가자나 라벨에 쏠리지
않았고 **참가자 160명은 모두 유지**됐다. 가장 많이 빠진 참가자도 recording 6개가
남았다.

# 3. 결과

## 3.1 성능이 크게 떨어졌다

| | 저번 실험 | **이번 실험** |
| --- | ---: | ---: |
| balanced accuracy | 1.0000 | **0.7626** |
| sensitivity | 1.000 | 0.718 |
| specificity | 1.000 | 0.807 |
| AUROC | 1.000 | 0.851 |
| 표준편차 | 0.0000 | 0.0412 |

**0.24 하락.** 저번 실험에서 모든 모델이 0.95를 넘었던 것은 모델이 좋아서가 아니라
문제가 쉬웠기 때문이라는 직접적인 증거다.

저번 실험의 tremor는 non_tremor보다 가속도 RMS가 17~24배 컸다. PADS 환자의 떨림은
그만큼 크지 않고, 대조군도 정지 상태가 아니라 과제를 수행 중이다.

**표준편차 변화가 그 못지않게 중요하다.** 저번 실험은 6개 fold가 모두 1.0000이라
모델 간 비교가 불가능했다. 이번에는 0.0412의 실제 변동이 있어 비교에 의미가 생긴다.

### fold별

| fold | 테스트 참가자 | BA | sensitivity | specificity | AUROC |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 1 | 32 | 0.7798 | 0.697 | 0.862 | 0.859 |
| 2 | 32 | 0.7616 | 0.767 | 0.756 | 0.845 |
| 3 | 32 | 0.7203 | 0.556 | 0.884 | 0.805 |
| 4 | 32 | 0.8223 | 0.810 | 0.835 | 0.901 |
| 5 | 32 | 0.7291 | 0.761 | 0.697 | 0.847 |

sensitivity가 specificity보다 일관되게 낮다. **저번 실험도 방향이 같았다** — 오분류
32건이 전부 떨림을 놓치는 false negative였다. 규모는 달라도 실패 방향은 동일하다.

## 3.2 주파수 feature의 기여가 처음으로 측정됐다

이 저장소의 핵심 연구 질문에 대한 답이며, **이번 실험의 가장 큰 기여**다.

| feature set | 저번 실험 | **이번 실험** |
| --- | ---: | ---: |
| B1 (시간 20개) | 0.9667 | 0.7003 |
| B2 (시간+주파수 52개) | 0.9750 | **0.7626** |
| **차이** | **+0.8%p** | **+6.2%p** |
| AUROC 차이 | 측정 불가 (양쪽 1.000) | **+8.3%p** (0.7679 → 0.8513) |

저번 실험까지 이 저장소는 네 번의 분석(로지스틱 회귀, 민감도 분석, 비선형 baseline,
gradient boosting)을 거쳤지만 주파수 효과가 +0.8%p에 그쳤고, 센서 조합과 window
길이를 바꾸면 **부호까지 뒤집혔다.** 포화 때문에 측정 해상도가 없었다.

참가자 160명에 난이도가 있는 데이터에서는 효과가 명확하다. 이 저장소가 처음으로
**"명시적 주파수 정보가 도움이 된다"**고 말할 수 있는 근거를 확보했다.

## 3.3 모델 간 차이가 사라졌다

| | 저번 실험 | **이번 실험** |
| --- | ---: | ---: |
| LightGBM B2 | 1.0000 | 0.7626 |
| XGBoost B2 | 0.9500 | 0.7610 |
| **차이** | **0.0500** | **0.0016** |

저번 실험의 0.05 차이는 알고리즘의 우열이 아니라 정규화 설정 하나의 효과였다.
XGBoost의 `min_child_weight=1.0`이 확신이 서면 분할을 막아버려 300개 트리 중
203개가 빈 껍데기가 됐던 현상이다(저번 실험 README 참고).

recording이 220개에서 1,569개로 늘자 그 차이가 사실상 소멸했다. **n이 작을 때의
모델 순위를 신뢰하면 안 된다**는 것을 같은 코드로 보여준 사례다.

## 3.4 남은 문제는 모델이 아니라 보정이다

참가자 단위(최대 확률 집계) 결과가 recording 단위보다 **나쁘다.**

| 관점 | BA | sensitivity | specificity | **AUROC** |
| --- | ---: | ---: | ---: | ---: |
| recording 단위 | 0.7626 | 0.718 | 0.807 | 0.851 |
| 참가자 단위 (max) | **0.6314** | 0.990 | **0.273** | **0.959** |

그런데 **AUROC는 오히려 0.959로 더 높다.** 순위 정보는 더 좋아졌는데 0.5 임계값이
틀린 것이다. 확률 분포를 보면 양쪽 모두 0.5 위에 몰려 있다.

| | 25% | 중앙값 | 75% |
| --- | ---: | ---: | ---: |
| 건강 대조군 | 0.471 | 0.660 | 0.836 |
| 환자 | 0.986 | 0.998 | 0.999 |

집계 방식과 임계값을 바꾸면 크게 달라진다.

| 집계 (임계값 0.5) | BA |
| --- | ---: |
| max | 0.627 |
| **mean** | **0.844** |
| median | 0.807 |

| 임계값 (max 집계) | BA | sensitivity | specificity |
| ---: | ---: | ---: | ---: |
| 0.5 | 0.627 | 0.988 | 0.266 |
| **0.9** | **0.881** | 0.901 | 0.861 |
| 0.99 | 0.821 | 0.667 | 0.975 |

> 위 임계값 표는 **진단용이다.** 테스트 데이터를 보고 고른 값이므로 성능 주장으로
> 쓸 수 없다. 실제로 쓰려면 train fold에서만 임계값을 정해야 한다.

### 저번 실험과 같은 패턴이다

저번 실험에서 오분류 32건이 전부 참가자 `march` 한 명에게 몰렸는데, **march fold를
포함한 모든 fold의 AUROC가 1.000**이었다. 순위는 완벽한데 고정 임계값이 틀린 것이
원인이었고, "참가자별 기준선 보정이 필요하다"는 결론으로 이어졌다.

| | 저번 실험 (march) | **이번 실험 (참가자 단위)** |
| --- | --- | --- |
| 정확도 | 낮음 (0.700~0.800) | 낮음 (0.631) |
| AUROC | **1.000** | **0.959** |
| 원인 | 고정 0.5 임계값 | 고정 0.5 임계값 |
| 규모 | 참가자 1명 | **참가자 160명** |

**참가자 한 명에게서 본 현상이 160명 규모에서 재확인됐다.** 우연이 아니라 구조적
문제라는 뜻이고, 개인별 기준선 보정이 다음 작업이라는 근거가 된다.

## 3.5 동작 과제별 — 저번 실험에 없던 축

저번 실험의 데이터는 동작 구분이 없어 이 분석이 불가능했다.

| 과제 | 성격 | B1 | B2 | 개선 |
| --- | --- | ---: | ---: | ---: |
| LiftHold | 자세 유지 | 0.679 | **0.766** | +8.6%p |
| RelaxedTask | 안정 + 인지 부하 | 0.718 | 0.762 | +4.5%p |
| HoldWeight | 부하 유지 | 0.709 | 0.757 | +4.8%p |
| StretchHold | 팔 뻗기 | 0.671 | 0.752 | +8.1%p |
| Relaxed | 안정 | 0.687 | **0.743** | +5.6%p |

**주파수 feature가 모든 과제에서 도움이 되고, B1이 약했던 과제일수록 더 크게
개선된다.** 시간 영역 feature만으로 부족한 부분을 주파수가 메운다는 해석과 맞는다.

**안정 상태(Relaxed)가 가장 낮다.** 파킨슨병은 안정 시 떨림이 특징이라 여기서 가장
잘 잡혀야 하는데 반대다. 약효가 도는 중이거나, 떨림이 간헐적이거나, 팔을 받치고
있어 신호가 약할 가능성이 있다. 별도 확인이 필요하다.

## 3.6 진단별 검출 — 저번 실험에 없던 축

LightGBM B2, 참가자 단위, 임계값 0.5, max 집계.

| 진단 | 인원 | 떨림으로 판정 | 비율 | 확률 중앙값 |
| --- | ---: | ---: | ---: | ---: |
| 본태성 떨림 | 21 | 21 | **1.000** | 0.999 |
| 파킨슨병 | 60 | 59 | 0.983 | 0.996 |
| 건강 대조군 | 79 | 58 | **0.734** | 0.660 |

환자는 거의 모두 잡지만 대조군의 73%가 오탐이다. 3.4의 보정 문제가 그대로 드러난다.
본태성 떨림이 파킨슨병보다 검출률이 높은 것은 본태성 떨림이 대체로 진폭이 크고
지속적이라는 임상 지식과 일치한다.

# 4. 한계

1. **라벨이 약하다.** 참가자 단위 진단에서 도출했다. 환자가 해당 20초 동안 실제로
   떨고 있었는지는 보장되지 않는다. 성능 하락의 일부는 모델이 아니라 라벨 잡음일 수
   있고, 현재 설계로는 둘을 분리할 수 없다. **저번 실험은 수집 시 지시로 라벨이
   확실했으므로, 이 항목은 두 실험을 직접 비교할 때 가장 큰 교란 요인이다.**
2. **편측성 떨림을 다루지 못했다.** 양 손목에 같은 라벨을 붙였다. 임상 소견의 좌/우
   표현을 파싱하면 개선 여지가 있다.
3. **약물 상태를 통제하지 않았다.** PADS는 복약 상태를 recording 단위로 제공하지
   않는다.
4. **임계값과 집계 방식이 고정값이다.** 3.4에서 보듯 여기가 가장 큰 개선 여지다.
5. **PADS만의 결과다.** 우리 데이터로 학습해 PADS로 평가하는 **전이 실험은 하지
   않았다.** 그것이 "모사 떨림이 실제 떨림의 대리물인가"에 대한 직접적인 답이 되며,
   다음 단계로 남는다.
6. 31개 recording이 다운로드 실패로 빠졌다(2%).

# 5. 다음 작업 제안

1. **train fold에서만 임계값을 정하는 절차를 추가한다.** 3.4 기준 가장 효과가 큰
   개선이고 새 데이터가 필요 없다.
2. **집계를 max에서 mean으로 바꾼다.** 같은 임계값에서 0.627 → 0.844.
3. **우리 데이터 → PADS 전이 실험을 수행한다.** 저장소의 외적 타당도에 직접 답한다.
4. 임상 소견에서 편측성을 파싱해 손목별 라벨을 정교화한다.
5. Relaxed 과제가 가장 낮은 원인을 확인한다.

# 6. 실행 방법

macOS에서 LightGBM과 XGBoost는 OpenMP 런타임이 필요하다.

```bash
brew install libomp
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pip install lightgbm==4.7.0 xgboost==3.4.1
```
